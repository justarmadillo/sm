# fsrs_dart

A pure Dart port of [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs)
5.4.1 — the Free Spaced Repetition Scheduler, FSRS-6. No Flutter dependency, no
code generation, no plugins.

The goal is an **identical** port: the same card, the same instant and the same
grade must produce the same schedule here as in ts-fsrs, down to the fuzzed day.
That claim is checked mechanically (see [Verification](#verification)) rather
than asserted.

```dart
import 'package:fsrs_dart/fsrs.dart';

final scheduler = fsrs();
final now = DateTime.utc(2022, 11, 29, 12, 30);

// All four outcomes, without committing to one.
final preview = scheduler.repeat(createEmptyCard(now), now);
print(preview[Rating.good].card.due);

// Or one grade directly.
final result = scheduler.next(createEmptyCard(now), now, Rating.good);
print('${result.card.state} due ${result.card.due}');

// Probability of recall right now.
print(scheduler.getRetrievabilityFormatted(result.card, now));
```

`js_compat.dart` has no counterpart upstream. It exists because three JavaScript
behaviours decide FSRS results and Dart disagrees with all three: `Math.round`
rounds halves toward `+Infinity` (Dart rounds away from zero), the Alea PRNG
relies on `>>> 0` / `| 0` coercion, and `String(number)` formats differently from
Dart's `double.toString()` — and the fuzz seed is a formatted number.

## Verification

```bash
cd fsrs-dart
dart pub get
dart test
dart analyze
```

Two independent vector suites, both regenerable:

**1. Identity with ts-fsrs** (`test/ts_fsrs_vectors_test.dart`, vectors in
`test/vectors/ts_fsrs_vectors.json`). Generated by running the reference
implementation itself:

```bash
npx tsx fsrs-dart/tool/gen_ts_vectors.mts --ts-fsrs <ts-fsrs>/packages/fsrs/src --out fsrs-dart/test/vectors/ts_fsrs_vectors.json
```

It covers 13 configurations (default, long-term, no steps, many steps, single
step, two retention settings, fuzz on in both scheduler modes, and v4/v5/custom
v6 weight vectors), each driven through a 25-review pseudo-random walk. Every
step compares all four preview cards and logs, the derived fuzz seed,
retrievability, `rollback`, and `forget` with and without a counter reset —
plus the algorithm primitives, the Alea stream, the fuzz windows, date helpers,
parameter migration and clipping, step layouts, and `reschedule`. Comparisons
are exact; doubles must match bit for bit.

**2. FSRS-6 agreement with py-fsrs 6.3.2** (`test/py_fsrs_vectors_test.dart`,
vectors in `test/vectors/py_fsrs_v6_vectors.json`):

```bash
python fsrs-dart/tool/gen_py_vectors.py --py-fsrs <py-fsrs> --out fsrs-dart/test/vectors/py_fsrs_v6_vectors.json
```

This is the check a faithful port of a *wrong* formula would fail: initial
stability and difficulty, next difficulty, short-term stability, stability after
recall and after a lapse, the interval formula at five retention settings, the
forgetting curve, and the memory-state trajectory of seven review sequences.

py-fsrs and ts-fsrs share the algorithm but not the card lifecycle, so the
cross-check deliberately covers the algorithm only, with three documented
differences:

- ts-fsrs rounds intermediates to 8 decimals and py-fsrs does not, so values are
  compared to a relative tolerance of `1e-6` with an absolute floor of `5e-9`.
- py-fsrs 6.3.2 floors stability at `0.001` but sets no ceiling; ts-fsrs also
  caps it at 36500 days. The cap is applied before comparing.
- py-fsrs has no `New` state and does not order the review-state intervals the
  way ts-fsrs does (`hard = min(hard, good)`, `good = max(good, hard + 1)`,
  `easy = max(easy, good + 1)`). Lifecycle behaviour is pinned by suite 1.

`test/behavior_test.dart` and `test/js_compat_test.dart` port the contract tests
from the ts-fsrs suite: rejected inputs and their messages, learning-step
exhaustion without skipping (upstream issue #311), strategy overrides, parameter
replacement semantics, calendar-date elapsed days, and the JavaScript numeric
semantics above.

## Intentional differences from ts-fsrs

Behaviour is identical; the surface is Dart.

- **Naming.** Fields and methods are camelCase (`scheduledDays`, `nextInterval`).
  JSON keys keep the upstream snake_case, so serialized cards move between
  ts-fsrs, py-fsrs and this package unchanged.
- **`State.newState`** rather than `State.New`; `new` is not usable as an
  identifier in Dart. The persisted integer values are unchanged.
- **`Rating` includes `manual`.** Dart has no equivalent of TypeScript's
  `Exclude<Rating, Manual>`, so a manual rating is rejected at runtime, with the
  same message upstream uses.
- **`afterHandler` overloads** become separate methods — `repeatWith`,
  `nextWith`, `rollbackWith`, `forgetWith`, `rescheduleWith` — because Dart
  cannot infer a generic return type from an absent argument.
- **No `Proxy`.** Upstream re-derives the interval modifier through a proxy on
  the parameter object; here, assignment goes through explicit setters
  (`requestRetention`, `w`, `enableShortTerm`, ...) or `updateParameters`.
  One upstream quirk is reproduced on purpose: replacing the whole parameter set
  migrates `w` against the *previous* relearning steps and short-term flag,
  because that is the order the proxy sees the keys in, and migrating against
  the new values would clip `w[17]`/`w[18]` differently.
- **Date prototype extensions** (`Date.prototype.scheduler`, `.diff`, `.format`,
  `.dueFormat`) are not ported; the free functions they delegate to
  (`dateScheduler`, `dateDiff`, `formatDate`, `showDiffMessage`) are.
